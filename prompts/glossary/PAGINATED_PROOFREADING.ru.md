# Постраничная вычитка крупных DOCX (канон)

> **Обязательно** для документов от ~50 виртуальных страниц и выше (диалоги 1000+ реплик, книги 300+ стр.).  
> Инструмент: `tools/page_batch_proofread.py` · прогресс: `.proofread_progress.json` (или аналог у заказчика).

---

## Железное правило

**Не читать и не править весь документ за один проход.**  
Идти **последовательно батчами**: прочитал → исправил → сохранил → зафиксировал прогресс → **только потом** следующий батч.

### Запрещено

- «Пробежать» оставшиеся страницы одним `run-all`, глобальным regex или auto-STT **вместо** чтения каждого батча.
- Перескакивать на стр. 800+, пока не вычитаны предыдущие батчи с правками.
- Считать батч «готовым», если применён только whitelist regex без прочтения текста батча.

### Разрешено как дополнение (не замена чтению)

- Узкий auto-STT whitelist **после** ручного чтения батча (для уже замеченных паттернов).
- Скрипт `export` / `apply` / `fill_message_paragraph` — только после списка правок из чтения.

---

## Цикл одного батча

1. **Экспорт** (весь батч в один файл, не фрагментами):
   ```bash
   python tools/page_batch_proofread.py export --start <N> --pages <P>
   ```
2. **Прочитать целиком** экспорт + 2 реплики контекста до/после (уже в файле).
3. **Список правок**: `msg <idx> (Спикер): было → стало` — только уверенные STT/пунктуация; спорное — пометка, не выдумывать.
4. **Применить** in-place (`apply` / `run` с ручными fixes), **не** `manual_proofread.py main()` на всём файле.
5. **Проверка**: счётчик реплик не уменьшился; подписи спикеров и цвета сохранены.
6. **Прогресс**: `last_completed_page = N+P-1`; краткий отчёт заказчику.
7. Следующий батч: `--start N+P`.

---

## Размер батча (страниц за один проход)

Виртуальная страница ≈ **1800 символов** параграфов DOCX (реплики + заголовки `📅`).  
Подбирай **P** по реальному контексту модели, а не «сколько влезет в один ответ».

| Класс модели | Примеры | Страниц **P** за проход | Примечание |
|--------------|---------|-------------------------|------------|
| **Полный контекст** | Claude Opus/Sonnet, GPT-4.1/4o, Cursor Agent, Composer, Gemini Pro | **10** | Комфортно: ~25–100 реплик, длинные монологи целиком |
| **Средний контекст** | GPT-4o mini, бесплатные чаты с лимитом, средние open-source | **3–5** | При длинных сложных монологах — ближе к 3 |
| **Узкий / бесплатный auto** | Kilocode auto free, малые локальные модели, агенты с жёстким лимитом токенов | **1–2** | Лучше 1 стр., если много текста на странице |

Если модель **не тянет 10 страниц внимательно** (сокращает, пропускает реплики, не возвращает список правок) — **уменьши P**, не отказывайся от постраничности.

## Приоритет внутри батча

1. Длинные монологи (особенно ≥1200 симв.).
2. Бессмысленные / кривые фразы (омофоны STT, склейки, обрывы).
3. Паузы STT (`что. Значит`) — см. [`STT_PROCESSING_ALGORITHMS.ru.md`](STT_PROCESSING_ALGORITHMS.ru.md).
4. Короткие реплики — только явные ошибки.
